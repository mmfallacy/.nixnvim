# Partial staging

Before proposing a group, identify files whose entire changes belong to it and files needing a selected slice. Whole files (tracked or untracked) use `git add -- <exact files>` after approval. Use explicit file paths only: no `git add .`, `-A`, globs, or directory paths. A split is feasible only if the patch can be reviewed in full and the index slice and worktree remainder each make sense without later groups.

For a **tracked** text file, inspect `git diff --no-ext-diff -- <exact path>` and form a patch with its file headers and only the complete hunks belonging to this group. For an **untracked** regular text file, read its full contents and form a small new-file patch with `diff --git a/<path> b/<path>`, `new file mode 100644`, `--- /dev/null`, `+++ b/<path>`, and `@@ -0,0 +1,N @@` followed by the selected `+` lines; `N` must equal the number of lines added to the staged new file. This index-only new-file method was verified: after application, the unstaged diff shows the remainder. Do not guess at file modes, newline handling, coupled edits, or large patches; request a file split if the exact patch or remainder cannot be reviewed confidently.

For either patch, review the full diff headers, context, and line counts before staging. Supply the **same patch** through quoted heredocs to `git apply --cached --check -` and then `git apply --cached -`; never use interactive `git add -p`, stage the entire shared file first, or apply a patch to the worktree. A clean apply does not prove the slice is correct. After staging, inspect `git status --short`, `git diff --cached --check`, the complete `git diff --cached --no-ext-diff`, and `git diff --no-ext-diff -- <split paths>`. The index must be exactly the approved group; the remainder must be coherent and match the planned later work. If checking or verification fails, stop and report it without silently unstaging or editing files.

**Scenario — declaration test now, assembly test later:** `tests/declarations.test.ts` contains both behaviors. If tracked with separate hunks, copy only the declaration hunk into the checked index-only patch. If untracked and small, use its read contents to construct a coherent new file containing only the declaration tests. In both cases, verify the assembly tests remain unstaged; if either slice requires later work to be valid, stop and ask for an edit instead.
